| 1 | F01 | `[G17]` "ID mismatch (Zeke, for now): when a linked record's HubSpot ID…" | 11/18 — Zeke: temporary External System ID, status and update rules. They are the same for BT/RBT and BCBA, and they replace the wording above and in the architecture tab where they differ. (1) A create that sends the HubSpot record ID as the temporary ID ends with last_sync_status = waiting and the reason "Waiting for the Workday ID". A create that sends workday_id ends with success. (2) While the record is waiting, field and label updates are still sent to CR. An update always sends the External System ID CR already holds. CR still holds the temporary ID and the checklist is not ticked → waiting. CR still holds the temporary ID and the checklist is ticked → error. The checklist is ticked and workday_id is blank → error. CR holds another value that differs from workday_id → error, and no update is sent. (5) Only that last case stops updates. A blank on either side is not a mismatch. |
